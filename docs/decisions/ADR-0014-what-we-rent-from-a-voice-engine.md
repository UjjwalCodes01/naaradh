# ADR-0014 — What we rent from a voice engine, and what we never delegate to one

**Status:** accepted
**Date:** 26 Sep 2026
**Deciders:** Founder (implemented by agent)
**Invariants touched:** 8, 13, 15, 17, 18
**Builds on** ADR-0006 (the brain is ours), ADR-0013 (adapters before the bake-off).

## Context

Retell's platform is much larger than a voice pipeline. Reading its documentation in full
(Sep 2026) turns up a knowledge base, CRM synchronisation to Salesforce/HubSpot/Dynamics/Zoho,
post-call analysis, A/B testing across live traffic, an AI copilot that edits agents, live call
monitoring with human takeover, analytics dashboards, AI QA scoring, contacts, chat and SMS
agents. Bolna's is smaller but heading the same way: workflows, campaigns, dispositions, its own
knowledge base.

Every one of those features is free to switch on from a dashboard, and several of them overlap
with something Naaradh already owns. The cost of switching one on is not the line item — it is
that the record of what happened moves outside our database, outside RLS, outside the consent
ledger, and outside the audit trail a merchant or a regulator would ask us for.

Nothing in the code stops an operator from enabling them, so the decision is written down here.

## Decision

**We rent the call. We never rent the record.**

The engine is allowed to do exactly four things: carry the audio, run the model's turn, invoke
our tools, and tell us what happened. Everything that stores, scores, decides or syncs is ours.

### Switched on, deliberately

| Feature | Why it is safe |
|---|---|
| Single-prompt agents | One agent per approved script version, generated by us from `call-scripts`. |
| Mid-call custom functions | The only way the model can learn anything; every call is authorised and written to `agent_actions` (invariant 18). |
| Call transfer (cold / warm / agentic warm) | Destination set by us per call from verified targets (invariant 19), never by the model. |
| Post-call extraction | The engine extracts; **our** outcome taxonomy decides what it means and what is billable. |
| Signed webhooks | Retell signs; Bolna does not, which is why E-23 exists. |
| Web calls | No number, no carrier, nothing dialled. An onboarding demonstration (see below). |

### Never switched on

| Feature | Why not |
|---|---|
| **Vendor knowledge base** | Retell's retrieval cannot cite which document it used. Invariant 18 requires the article the agent quoted to be identifiable, and a retracted or unpublished article must stop being reachable the moment it is retracted — neither holds inside a vendor's vector store. Ours is Postgres full-text search behind a tool, per tenant, under RLS. |
| **CRM / helpdesk sync** | Exports customer records to a third party outside the consent ledger, outside RLS and outside our DPA chain. Merchant CRM data flows **into** us (`crm/`), never out through the engine. |
| **Live A/B testing** | Splits real customers between agent versions. A merchant approved a script as a whole, and billing and attribution assume one approved `script_version` per call. If we ever want it, both variants are approved rows in our `scripts` table and we do the splitting. |
| **Agent-editing copilots** (Conductor and equivalents) | Edits agents out of band. A call would then run on wording nobody approved, which breaks script approval and the disclosure guarantee (invariant 7). |
| **Vendor analytics, AI QA, contacts** | We already have these, tied to our outcome taxonomy, our dispute process and our billing. Two sources of truth about call volume is worse than one. |
| **Vendor SDKs in product code** | Invariant 13. `engines/<vendor>` speaks HTTP over `fetch`; nothing else imports a vendor at all. |
| **Human takeover of a live call** | Our model has no such state: a call belongs to the agent or is transferred to a verified target. Listening to a live call is evidence access — role-gated, audited, and only through the staff console if we ever build it. |

### Data kept at the vendor

Set every engine account to the **shortest retention it offers** (Retell: one day, per agent).
We persist the recording and transcript into our own CMEK bucket while handling `call_ended`,
so the vendor's copy is a cache, not the record. This is also why a failed persist is not
retried: Retell serves a recording URL for about ten minutes and then deletes it.

## Consequences

- A feature comparison that says "the vendor already does this" is not an argument for using it.
  The question is always: after this call, where does the record live, and who can read it?
- Switching engines stays cheap, because nothing about a merchant lives inside one.
- We carry work the vendor would have done for us — knowledge search, QA, analytics, CRM — and
  that work is the product.
- If a merchant ever demands a vendor feature from this list, it is a product decision and a new
  ADR, not a dashboard toggle.

## Web calls, and one open boundary

`createWebCall` is on the adapter because it solves a real problem: a merchant can hear their own
agent — real script, real voice, real tools — before any phone number, DLT registration or
carrier exists. It places no call, so no gate, consent or calling window applies; the greeting is
still the approved first utterance, so the AI and recording disclosure is spoken as always.

What is **not** decided here: the browser half. Joining a web call needs the vendor's own
browser client, and invariant 13 says no vendor SDK outside `engines/<vendor>/`. Either that
boundary gets a written exception for one lazily-loaded client component, or we do not ship the
merchant-facing button. Recorded as Q-36; the adapter is ready either way.
